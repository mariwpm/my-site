## Ответы на вопросы

### Чем отличается CI от CD?

**CI (Continuous Integration)** — непрерывная интеграция. При каждом `push` в репозиторий автоматически собирается код и запускаются тесты и линтеры. Это позволяет быстро находить ошибки.

**CD (Continuous Delivery/Deployment)** — непрерывная доставка/развёртывание. Отвечает за автоматическую доставку кода на сервер. В варианте Delivery — развёртывание инициируется вручную, в варианте Deployment — автоматически после успешных тестов.

### Что произойдёт, если тесты завершатся ошибкой на этапе CI?

Пайплайн остановится, последующие шаги (build, deploy) не выполнятся. Код не попадёт в продакшен. Разработчик получит уведомление об ошибке. Это защищает от попадания неработоспособного кода на сайт.

### Для чего используется директива `needs: ci` в задаче развёртывания?

Директива `needs: ci` устанавливает зависимость: задача `deploy` запустится только после успешного завершения задачи `ci`. Если CI упал — деплой не выполняется. Это гарантирует, что на продакшен попадёт только проверенный код.

### Что такое артефакт и для чего он передаётся между задачами?

**Артефакт** — это файлы, сохранённые после выполнения одной задачи, которые доступны другим задачам. В нашем случае задача `ci` собирает проект в папку `dist/` и сохраняет её как артефакт `site-build`. Задача `deploy` скачивает этот артефакт и публикует на GitHub Pages. Это позволяет не собирать проект повторно в задаче деплоя.

### Почему развёртывание не запускается на Pull Request?

В задаче `deploy` указано условие `if: github.ref == 'refs/heads/main'`. Оно разрешает выполнение деплоя только для ветки `main`. При создании Pull Request изменения находятся в другой ветке (`feature/x`), поэтому деплой не срабатывает. Это защищает продакшен от непроверенного кода и позволяет сначала проверить код через CI.

## Эксперименты

### Эксперимент 1. Ошибка линтера

Добавлен незакрытый тег `<p>` в `index.html` → пайплайн упал на шаге `lint` → деплой не запустился.

### Эксперимент 2. Ошибка теста

Изменён скрипт `test` на `exit 1` → пайплайн упал на шаге `test` → деплой не запустился.

### Эксперимент 3. Pull Request

Создана ветка `feature/x`, открыт PR #1 → запустилась только задача `ci` (Lint & Test), задача `deploy` пропущена, так как сработало условие `if: github.ref == 'refs/heads/main'`.
